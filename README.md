# DS 건강검진센터 인턴 미션

교사 연수용 데이터 과학 챌린지입니다. 참가 팀은 DS 건강검진센터의 데이터 분석 인턴이 되어 검진 기록으로 뇌졸중 위험 모델을 만들고, 채점용 검진자 13,020명 가운데 상담 전화를 걸 사람의 번호 목록을 제출합니다. 캐글과 같은 방식으로 정답은 서버에만 있고, 공개 절반의 점수는 순위판에 바로 표시되며 최종 절반의 점수는 진행자가 공개할 때 열립니다.

서버 없이 정적 파일만으로 동작합니다. 모델 학습은 브라우저 안의 파이썬(stlite)이 하고, 등록·제출·채점은 수파베이스의 함수가 맡습니다.

## 구조

| 자리 | 파일 | 하는 일 |
|---|---|---|
| 첫 화면·순위판(참가자용) | `index.html` · `app.js` · `assets/board.css` | 센터장의 편지, 미션 요약, 진행 순서, 순위판(시상대·순위표·시간에 따른 기록). 5초마다 새로 읽습니다 |
| 순위판(진행자용) | `host.html` | 관리자 암호를 넣으면 소속·성명·이메일과 팀별 설정, 공개 전의 최종 점수가 보입니다. 최종 점수 공개, 마감 설정, 안내용 CSV, 메일 쓰기. **참가자와 공유하지 않습니다** |
| 실습실 | `app/` | 데이터 탐색 → 분류 모델 → 채점표 → 성능 높이기(인턴 등록·전화 목록 제출) → 모델 소개 |
| 데이터 | `data/` | `train.csv`(30,380명, 정답 있음) · `test.csv`(13,020명, 정답 없음) · `sample_submission.csv`(제출 양식) · 출처는 `data/README.md` |
| 스키마 | `schema.sql` | 표 4개와 함수 7개. 공개 키는 표를 직접 읽지 못하고 함수만 부릅니다 |
| 설정 | `config.js` | 수파베이스 주소·공개 키·행사 이름·데이터 주소·모델 소개 폼 주소 |
| 정답 | `_private/` | `labels.sql`·`test_labels.csv`. test의 정답과 공개/최종 구분. **저장소에 올리지 않습니다**(`.gitignore`) |

## 행사 여는 순서

1. 수파베이스 SQL Editor에 `schema.sql` 전체를 붙여 넣고 실행합니다.
2. `_private/labels.sql`을 붙여 넣고 실행합니다. 이 파일은 저장소에 없습니다. 진행자가 원본 검진 기록으로 직접 만듭니다.
   ```bash
   python3 scripts/make_split.py <원본 csv>
   ```
   `data/`의 세 파일과 `_private/`의 두 파일이 함께 만들어집니다.
3. 행사를 등록합니다. 관리자 암호는 이때 정하며, 길고 짐작하기 어렵게 만듭니다.
   ```sql
   insert into public.stroke_challenge_event (event_id, title, deadline, max_submissions, admin_pass)
   values ('교사연수-2026', 'DS 건강검진센터 인턴 미션', '2026-10-15 18:00:00+09', 40, '여기에-관리자-암호');
   ```
   마감을 비워 두려면 `deadline`에 `null`을 넣습니다. 마감은 나중에 `host.html`에서 바꿀 수 있습니다.
4. `config.js`의 `EVENT`를 3에서 정한 `event_id`와 같게 맞춥니다.
5. 이 폴더를 GitHub Pages에 배포합니다. 로컬 확인은 `python3 -m http.server 4052`.
6. 참가자에게는 첫 화면(`index.html`)과 실습실(`app/`) 주소만 알립니다. `host.html` 주소와 관리자 암호는 알리지 않습니다.

순위판이 "순위판이 아직 열리지 않았습니다"를 표시하면 1~3 가운데 빠진 단계가 있는 것입니다. "행사를 찾지 못했습니다"는 4의 `EVENT`가 등록한 이름과 다를 때 표시됩니다.

## 규칙

- **평가 지표는 F2**입니다. 정밀도 P = 찾은 환자 ÷ 전화한 사람, 재현율 R = 찾은 환자 ÷ 전체 환자, F2 = 5·P·R ÷ (4·P + R). 재현율을 정밀도의 두 배로 칩니다. 전화한 사람이 0명이거나 찾은 환자가 0명이면 계산하지 않습니다.
- **공개와 최종**: test 13,020명을 환자 비율이 같도록 층화해 공개 절반과 최종 절반으로 나눴습니다(현재 각 6,510명, 환자 각 122명. 순위판은 서버 값을 표시합니다). 제출하면 공개 절반의 점수가 바로 순위판에 오릅니다. 최종 절반의 점수는 진행자가 공개하기 전까지 서버에만 있습니다.
- **팀 점수와 순위**: 팀의 공개 F2 최고 기록이 팀 점수입니다. 같은 점수면 그 점수를 먼저 낸 팀이 앞서므로 같은 순위는 없습니다.
- **최종 순위**: 각 팀의 공개 최고 기록(같은 제출)을 최종 절반으로 다시 채점한 F2로 매깁니다. 캐글의 비공개 순위판과 같은 방식입니다. 최종 순위 화면에는 공개 순위와 비교한 변동(▲·▼)이 표시됩니다.
- **전화 목록 크기**: 한 번에 50명 이상을 제출해야 합니다. 서버가 50명 미만의 목록을 받지 않습니다.
- **팀 열쇠**: 등록하면 팀 열쇠가 나오고 제출할 때 필요합니다. 다른 컴퓨터에서 이어 하려면 열쇠를 옮겨 적습니다.
- **제출 상한**: 팀당 제출 횟수는 행사 등록 때 정한 `max_submissions`(기본 40번)까지입니다. 마감이 지나면 서버가 제출을 받지 않습니다.
- **한계**: 검진 기록 원본은 인터넷에 공개되어 있어, 마음먹으면 원본과 대조해 정답을 맞출 수 있습니다. 원본 id로 바로 찾지 못하도록 train과 test의 번호를 새로 매겼지만, 나이·혈당 같은 값으로 대조하는 것까지 막을 수는 없습니다. 이 챌린지는 연수 참가자끼리의 학습용이며 상금이 걸린 공개 대회에는 사용하지 않습니다.
- 순위의 앞자리는 표본 잡음이 큽니다. 공개 1등이 최종에서 밀리는 일이 자주 일어나며, 이것이 마무리에서 다룰 내용입니다. `research/RESULTS.md` 참고.

## 개인정보

- **수집 항목**: 팀명(순위판에 공개), 소속, 성명, 이메일. 실습실의 인턴 등록 화면에서 동의를 받은 뒤 수집합니다.
- **목적**: 최종 순위 안내와 연락.
- **보유 기간**: 행사 종료 후 30일 이내 파기합니다.
- **전화번호를 받지 않는 이유**: 결과 안내는 이메일로 충분하고, 목적에 필요한 최소한만 수집한다는 원칙을 따릅니다.
- **열람 범위**: 소속·성명·이메일이 든 표는 공개 키로 읽을 수 없습니다. 관리자 암호를 넣은 `host.html`에서만 함수로 열람합니다. 관리자 암호는 진행자의 브라우저 탭(세션 저장소)에만 남습니다.
- **파기**: 행사가 끝나면 SQL Editor에서 실행합니다.
  ```sql
  delete from public.stroke_challenge_team where event_id = '교사연수-2026';
  delete from public.stroke_challenge_log  where event_id = '교사연수-2026';
  ```
  내려받은 안내용 CSV도 같은 기한 안에 지웁니다.

## 최종 발표 절차

1. `host.html`을 열고 관리자 암호를 넣습니다. 진행자 화면은 관리자 함수(`stroke_challenge_admin_info`)로 최종 절반의 환자 수를 받아, 공개 전에도 최종 F2와 최종 순위를 미리 보여 줍니다.
2. 「최종 점수 공개」를 누릅니다. 참가자 순위판에 「최종 결과 발표」 배지와 「공개 순위 / 최종 순위」 전환 버튼이 표시되고, 최종 순위와 변동이 열립니다. 잘못 눌렀다면 「공개 취소」로 되돌립니다.
3. 「안내용 CSV 내려받기」로 팀명·소속·성명·이메일·공개 순위·공개 F2·최종 순위·최종 F2·안내 인원·찾은 환자·제출 횟수를 받습니다(UTF-8 BOM, 엑셀에서 바로 열림). 안내 인원과 찾은 환자는 팀 최고 기록의 test 전체(공개+최종) 기준입니다.
4. 「메일 쓰기」를 누르면 등록한 이메일 전체가 숨은참조로 들어간 메일 창이 열립니다. 제목과 순위판 주소가 미리 적혀 있습니다.
