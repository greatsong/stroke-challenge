# 뇌졸중 예측 챌린지 (독립 실행본)

당곡고 『데이터 과학』 12차시의 「성능 높이기 챌린지」를 교재에서 떼어 낸 것입니다. 서버 없이 정적 파일만으로 돌아갑니다.
브라우저 안에서 파이썬(stlite)이 모델을 학습해 채점하고, 기록은 수파베이스 표 하나에 쌓이며, 순위판이 5초마다 읽어 그립니다.

| 자리 | 파일 | 하는 일 |
|---|---|---|
| 순위판(참가자용) | `index.html` · `app.js` | 목표별 순위·시상대·시간에 따른 기록. 모델 이름만 보인다 |
| 순위판(진행자용) | `host.html` | 팀마다 고른 설정과 「확인 필요」(정답표와 맞지 않는 기록)가 보인다. **참가자와 공유하지 않는다** |
| 실습실 | `app/` | 데이터 소개 → 탐색 → 분류 모델 → 채점표 → 성능 높이기(기록 올리기) → 모델 소개 |
| 정답표 | `key.js` | 열 수 있는 모든 설정의 (안내 인원, 찾아낸 환자). 순위판이 올라온 기록을 이 표와 대조한다 |
| 설정 | `config.js` | 수파베이스 주소·공개 키·표 이름·행사 이름·제출 폼 주소·최종 순위 공개 여부 |
| 스키마 | `schema.sql` | 수파베이스 SQL Editor에서 한 번 실행한다 |

## 행사 열기

1. `schema.sql`을 수파베이스 SQL Editor에 붙여 넣고 실행합니다. 표 `stroke_challenge_log`가 생깁니다. 한 표로 여러 행사를 치릅니다.
2. `config.js`의 `EVENT`에 행사 이름을 적습니다. 기록마다 이 이름이 저장되고 순위판은 이 이름의 기록만 읽습니다.
3. `FORM_URL`(모델 소개 제출 폼, 없으면 비움)을 정하고 `REVEAL`은 `false`로 둡니다.
4. 이 폴더를 GitHub Pages 같은 정적 호스팅에 올립니다. 로컬 확인은 `python3 -m http.server 4052`.
5. 참가자에게는 순위판 주소와 실습실 주소만 알립니다. `host.html` 주소는 알리지 않습니다.

## 규칙

- **겨루는 동안**: 테스트 데이터의 F1로 순위를 매깁니다(공개 순위). 점수가 같으면 그 점수를 먼저 올린 팀이 앞섭니다.
- **마감 뒤**: 각 팀의 F1 최고 기록을 F2(재현율을 정밀도의 두 배로 치는 식)로 다시 매겨 최종 순위를 냅니다. `config.js`의 `REVEAL`을 `true`로 바꾸면 참가자 순위판에도 최종 순위 버튼이 열립니다. 진행자용(`host.html`)은 늘 볼 수 있습니다.
- 입력 속성 9개: 나이·평균 혈당·체질량지수·고혈압·심장병·결혼 여부·현재 흡연·자영업·남성. 가중치는 켠 채 고정, 빈 값은 「지운다」가 기본, 기준값 0.05~0.95는 두 모델에 모두 적용됩니다.
- 최댓값(정답표 기준): F1 0.3439(찾아낸 환자 38명 · 안내 139명), F2 0.4726(62명 · 328명). F1 1등 모델과 F2 1등 모델이 다릅니다. 이 차이가 마무리에서 보여 줄 내용입니다.
- 순위의 앞자리는 잡음이 큽니다(환자 82명, F1 표준오차 약 0.04). `research/RESULTS.md` 참고.

## 정답표 다시 만들기

실습실의 계산 환경(Pyodide 0.29.3 · scikit-learn 1.7.0)에서 만들어야 합니다. 컴퓨터의 scikit-learn으로 만들면 깊은 트리 몇 칸이 달라져 정상 기록이 「확인 필요」로 빠집니다.

```bash
npm i pyodide@0.29.3
NODE_PATH=$PWD/node_modules node scripts/build_key_pyodide.mjs
```

모델·분할·기준값 범위를 바꾸면 반드시 다시 만듭니다.
